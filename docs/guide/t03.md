# 3. 泛型

**一句话定位**：泛型是**编译期的类型检查 + 编译期自动插入强制转换**，运行期类型参数已经被擦除，所以它不产生任何运行时开销，也拿不到真实的类型参数。

## 一、没有泛型会怎样

JDK 5 之前，集合只能存 `Object`：

```java
List list = new ArrayList();
list.add("hello");
list.add(100);              // 编译通过，运行时才炸
String s = (String) list.get(1);   // ClassCastException
```

两个问题：

| 问题 | 说明 |
| --- | --- |
| 类型不安全 | 编译期发现不了类型错误，错误被推迟到运行期 |
| 到处强转 | 每次 `get` 都要 `(String)`，强转写错同样是运行期异常 |

泛型把这两个问题都搬到编译期：`List<String> list` 之后，`add(100)` 直接编译失败，`get()` 也不再需要强转。

## 二、类型擦除擦掉了什么

Java 的泛型是**伪泛型**：`javac` 编译时检查类型，然后把类型参数擦掉，生成的字节码里不存在 `List<String>`，只有一个普通的 `List`。

擦除规则：

| 声明 | 擦除后 |
| --- | --- |
| `List<String>` | `List` |
| `List<T>` | `List` |
| `T extends Comparable<T>` | `Comparable` |
| `T extends Number & Comparable<T>` | `Number`（第一个边界） |
| `T`（无边界） | `Object` |

所以这两行在运行时完全等价：

```java
List<String> a = new ArrayList<>();
List<Integer> b = new ArrayList<>();
System.out.println(a.getClass() == b.getClass());   // true，都是 java.util.ArrayList
```

真实类型信息只剩两处痕迹：

1. **编译期插入的 `checkcast`**。`String s = list.get(0)` 脱糖后是 `String s = (String) list.get(0)`，取出来时检查一次。
2. **`Signature` 属性**。类文件里保留了一份泛型签名，给编译器和反射用：

```java
Method m = MyClass.class.getMethod("method", List.class);
Type t = m.getGenericParameterTypes()[0];   // java.util.List<java.lang.String>
```

这就是为什么 Spring、Jackson、MyBatis 能通过 `ParameterizedType` 拿到泛型参数——不是靠运行时认识泛型，而是靠读类文件里的签名。

## 三、通配符：`? extends` 与 `? super`

先记住一条：**`List<Object>` 不是 `List<String>` 的父类型**。如果允许这种赋值，就能往“字符串列表”里塞 `Integer`，类型安全瞬间失效。所以泛型是不变的（invariant）。

需要“能接收一组相关类型”时，用通配符：

| 写法 | 名字 | 能读吗 | 能写吗 |
| --- | --- | --- | --- |
| `List<? extends Number>` | 上界通配符 | ✅ 读出来是 `Number` | ❌ 不能 add（编译器不知道具体是 Integer 还是 Double） |
| `List<? super Integer>` | 下界通配符 | ⚠️ 只能读成 `Object` | ✅ 可以 add `Integer` |
| `List<?>` | 无界通配符 | ⚠️ 只能读成 `Object` | ❌ 只能 add `null` |

**PECS 原则**（Producer Extends, Consumer Super）：

- 只是**生产**数据给你读 → `extends`
- 只是**消费**你写进去的数据 → `super`

JDK 里的标准范例是 `Collections.copy`：

```java
public static <T> void copy(List<? super T> dest, List<? extends T> src)
```

`src` 是生产者，用 `extends`；`dest` 是消费者，用 `super`。这样 `copy(List<Object>, List<String>)` 也能合法调用。

另一个坑：`List<? extends Number>` 不能 add，不是因为“只读”，而是因为编译器无法证明写入的元素类型和列表实际类型一致。`add(null)` 是唯一允许的，因为 `null` 属于任何引用类型。

## 四、泛型用不了的六个地方

擦除带来一串限制，面试常问“为什么”：

| 限制 | 原因 |
| --- | --- |
| `new T()` 不行 | 擦除后 `T` 是 `Object`，运行时不知道构造哪个类 |
| `new T[10]` 不行 | 数组是协变的且运行时要检查元素类型，泛型信息已丢失；只能 `(T[]) new Object[10]` 加 `@SuppressWarnings` |
| `instanceof List<String>` 不行 | 运行时没有 `List<String>` 这个类型，只能 `instanceof List` |
| 静态成员不能用 `T` | `T` 属于实例，静态成员在类加载时就存在，此时还没有类型参数 |
| `catch (T e)` 不行 | 异常类型必须在运行期确定 |
| `int` 不能做类型参数 | 类型参数必须是引用类型，用 `Integer` 代替；这也是 `List<Integer>` 有装箱开销的根源 |

还有一个隐蔽的：**擦除后签名相同的重载会冲突**。

```java
void print(List<String> list) {}
void print(List<Integer> list) {}   // 编译错误：name clash，两个方法擦除后都是 print(List)
```

## 五、桥方法（Bridge Method）

泛型类被继承、方法被覆写时，擦除会造成“子类方法签名和父类不一致”，编译器靠**桥方法**补上这一层。

```java
class Box<T> {
    T get() { return null; }
}
class StringBox extends Box<String> {
    @Override String get() { return "x"; }
}
```

擦除后父类是 `Object get()`，子类是 `String get()`——这不是覆写，是多了一个重载。编译器于是在 `StringBox` 里生成一个桥方法：

```java
// javap -c StringBox 可以看到
Object get() {
    return this.get();   // 转调真正的 String get()
}
```

所以 `Box<String> b = new StringBox(); b.get()` 才能多态到子类实现。桥方法上的 `ACC_BRIDGE` 和 `ACC_SYNTHETIC` 标志可以用反射看到。

## 六、面试连环问

**Q：泛型是编译期还是运行期特性？**

编译期。`javac` 做类型检查并插入 `checkcast`，之后擦除；运行期 `ArrayList` 里就是 `Object[]`，没有任何类型参数。

**Q：那为什么反射能拿到 `List<String>`？**

类文件的 `Signature` 属性里存了泛型签名。`getGenericParameterTypes()` / `getGenericSuperclass()` 读的是这份元数据，不是虚拟机的类型系统。所以 `new ArrayList<String>().getClass()` 拿不到 `String`，但 `字段/方法/父类` 上的泛型声明能拿到。

**Q：`List<?>` 和 `List<Object>` 有什么区别？**

`List<Object>` 可以 add 任何对象；`List<?>` 几乎不能写（只能 `null`），因为编译器不知道它实际指向什么类型。`List<?>` 是“只读视图”的语义。

**Q：为什么 Java 不学 C# 做具现化泛型？**

历史包袱。Java 5 引入泛型时已有海量非泛型类库，擦除能让新旧代码二进制兼容（`List` 和 `List<String>` 是同一个类，老 jar 不用重编译）。代价是运行期类型信息丢失、不能 `new T()`、基本类型要装箱。C# 的泛型在 CLR 层面实现，`List<int>` 是真实类型，没有装箱开销，但无法与旧的非泛型集合无缝互操作。

**Q：`Arrays.asList` 返回的 List 为什么不能 add？**

它返回的是 `Arrays` 内部的 `ArrayList`（不是 `java.util.ArrayList`），底层直接包装原数组，长度固定，`add/remove` 抛 `UnsupportedOperationException`。要可变就 `new ArrayList<>(Arrays.asList(...))`。
