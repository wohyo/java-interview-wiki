# 30. Spring AOP

**一句话定位**：AOP 把横切逻辑（事务、日志、权限、缓存）从业务代码里抽出来，通过**代理**在方法调用前后织入；Spring 用 JDK 动态代理或 CGLIB 生成代理对象。

## 一、五个核心概念

| 概念 | 含义 | 例子 |
| --- | --- | --- |
| Aspect（切面） | 横切关注点的模块化，`@Aspect` 类 | 日志切面 |
| JoinPoint（连接点） | 程序执行中可以插入逻辑的点 | 方法调用、异常抛出 |
| Pointcut（切点） | 匹配连接点的表达式 | `execution(* com.foo.service.*.*(..))` |
| Advice（通知） | 在连接点执行的逻辑 | `@Before`、`@Around` |
| Weaving（织入） | 把通知应用到目标对象的过程 | Spring 在 Bean 初始化后生成代理 |

## 二、代理方式

| 维度 | JDK 动态代理 | CGLIB |
| --- | --- | --- |
| 前提 | 目标类**实现接口** | 目标类**能被继承**（非 final） |
| 原理 | `Proxy.newProxyInstance` 生成实现接口的类 | ASM 生成子类，覆写方法 |
| 拦截入口 | `InvocationHandler.invoke()` | `MethodInterceptor.intercept()` |
| 创建速度 | 快 | 慢（生成字节码） |
| 调用速度 | Java 8+ 接近原生 | 略快（子类直接调用） |
| Spring 默认 | 有接口用 JDK | 无接口用 CGLIB |

Spring Boot 2.x 起 `spring.aop.proxy-target-class` 默认 `true`，**统一用 CGLIB**。原因是 CGLIB 代理的是类，注入时不会出现“只能按接口注入”的问题。代价是 final 类和 final 方法无法代理。

代理在 `BeanPostProcessor#postProcessAfterInitialization` 阶段生成（`AbstractAutoProxyCreator`），这也是为什么**同类方法内部调用不走代理**——调用发生在原始对象内部，没有经过代理。

## 三、五种通知与执行顺序

```java
@Aspect
@Component
public class LogAspect {

    @Pointcut("execution(* com.example.service..*.*(..))")
    public void servicePointcut() {}

    @Around("servicePointcut()")
    public Object around(ProceedingJoinPoint pjp) throws Throwable {
        System.out.println("around-before");
        try {
            Object result = pjp.proceed();
            System.out.println("around-after-return");
            return result;
        } catch (Throwable t) {
            System.out.println("around-after-throwing");
            throw t;
        } finally {
            System.out.println("around-after-finally");
        }
    }

    @Before("servicePointcut()")
    public void before() { System.out.println("before"); }

    @AfterReturning(pointcut = "servicePointcut()", returning = "ret")
    public void afterReturning(Object ret) { System.out.println("afterReturning"); }

    @AfterThrowing(pointcut = "servicePointcut()", throwing = "ex")
    public void afterThrowing(Throwable ex) { System.out.println("afterThrowing"); }

    @After("servicePointcut()")
    public void after() { System.out.println("after"); }
}
```

正常返回时的顺序：

```
around-before → before → 目标方法 → afterReturning → after → around-after-return → around-after-finally
```

异常时的顺序：

```
around-before → before → 目标方法抛异常 → afterThrowing → after → around-after-throwing → around-after-finally
```

记忆：`@Around` 包裹其他所有通知，`@After` 相当于 finally（无论正常还是异常都执行），`@AfterReturning` 只在正常返回时执行。

多个切面时的顺序用 `@Order` 控制：**值越小优先级越高**，进入时高优先级先执行，退出时高优先级后执行（像栈）。

## 四、切点表达式

| 表达式 | 匹配 |
| --- | --- |
| `execution(* com.foo.service.UserService.*(..))` | UserService 的所有方法 |
| `execution(public * com.foo..*.*(..))` | com.foo 包及子包下所有 public 方法 |
| `@annotation(org.springframework.transaction.annotation.Transactional)` | 带 `@Transactional` 的方法 |
| `within(com.foo.service..*)` | 指定包下所有类的所有方法 |
| `bean(*Service)` | Bean 名字以 Service 结尾 |
| `args(java.lang.String)` | 第一个参数是 String 的方法 |

`execution` 的完整格式：

```
execution(修饰符? 返回类型 包.类.方法名(参数) 异常?)
```

`*` 匹配任意字符，`..` 匹配任意层包或任意个参数。

## 五、@Transactional 失效的七种场景

这是面试最高频的追问。

### 1. 同类方法内部调用

```java
@Service
public class OrderService {
    public void create() {
        this.deduct();          // 直接调 this，不走代理
    }

    @Transactional
    public void deduct() { /* ... */ }
}
```

`this.deduct()` 是在原始对象上调用，代理没有介入，事务注解不生效。

解决：

```java
// 方案一：注入自身代理
@Autowired private OrderService self;
self.deduct();

// 方案二：AopContext（需开启 exposeProxy）
((OrderService) AopContext.currentProxy()).deduct();

// 方案三：拆到另一个 Bean（最推荐）
```

### 2. 方法不是 public

Spring 默认只代理 public 方法。`protected`、`private` 方法上的 `@Transactional` 不生效（CGLIB 也无法覆写 private）。

### 3. 异常被吞掉

```java
@Transactional
public void create() {
    try {
        orderDao.insert(order);
        throw new RuntimeException("失败");
    } catch (Exception e) {
        log.error("出错了", e);      // 没有继续抛出，事务提交
    }
}
```

事务是否回滚取决于**异常是否传播到代理层**。catch 后不抛，代理认为方法正常返回，直接提交。

### 4. rollbackFor 没配

`@Transactional` 默认只对 `RuntimeException` 和 `Error` 回滚，**受检异常不回滚**：

```java
@Transactional
public void create() throws IOException {
    orderDao.insert(order);
    throw new IOException("IO 失败");   // 默认不回滚！
}
```

解决：`@Transactional(rollbackFor = Exception.class)`。

### 5. 传播行为设置不当

`REQUIRES_NEW` 会挂起当前事务、新开一个事务，内外事务互不影响；`NESTED` 是嵌套事务（保存点），外层回滚会带着内层一起回滚。选错传播行为会导致“该回滚的没回滚”或“不该回滚的跟着回滚”。

### 6. 多数据源/多线程

`@Transactional` 绑定的是当前线程的 `DataSource`。多数据源时如果没有正确配置事务管理器，事务只作用于默认数据源；在子线程里执行 SQL 不受父线程事务管理。

### 7. 类没有被 Spring 管理

自己 `new` 出来的对象、没有 `@Service`/`@Component` 的类，Spring 不会为它生成代理。

## 六、七种事务传播行为

| 传播行为 | 当前有事务 | 当前无事务 |
| --- | --- | --- |
| `REQUIRED`（默认） | 加入当前事务 | 新建事务 |
| `REQUIRES_NEW` | 挂起当前事务，新建独立事务 | 新建事务 |
| `SUPPORTS` | 加入当前事务 | 以非事务方式执行 |
| `NOT_SUPPORTED` | 挂起当前事务，非事务执行 | 非事务执行 |
| `MANDATORY` | 加入当前事务 | **抛异常** |
| `NEVER` | **抛异常** | 非事务执行 |
| `NESTED` | 创建嵌套事务（保存点） | 新建事务 |

最常用的是 `REQUIRED` 和 `REQUIRES_NEW`。`NESTED` 只对 `DataSourceTransactionManager` 有效（依赖 JDBC 保存点）。

## 七、AOP 与拦截器、过滤器的区别

| 维度 | Filter | Interceptor | AOP |
| --- | --- | --- | --- |
| 所在层 | Servlet 容器 | Spring MVC | Spring 容器 |
| 拦截对象 | 所有请求 | Controller 方法 | 任意 Spring Bean 方法 |
| 能否拿到方法参数 | ❌ | ✅ | ✅ |
| 能否拿到 Bean | ❌ | ✅ | ✅ |
| 典型用途 | 编码、跨域、日志 | 登录校验、权限 | 事务、缓存、日志、限流 |

## 八、面试连环问

**Q：AOP 的原理？**

Spring 在 Bean 初始化后（`BeanPostProcessor#postProcessAfterInitialization`）判断是否匹配切点，匹配则生成代理对象：有接口用 JDK 动态代理，无接口用 CGLIB。调用代理方法时先执行通知链，再调用目标方法。

**Q：JDK 代理和 CGLIB 的区别？**

JDK 基于接口，生成实现同一接口的类，通过 `InvocationHandler` 拦截；CGLIB 基于继承，生成子类覆写方法，通过 `MethodInterceptor` 拦截。前者要求有接口，后者要求类/方法非 final。Spring Boot 2.x 默认用 CGLIB。

**Q：@Transactional 为什么会失效？**

本质是“调用没有经过代理”或“异常没有传播到代理”。七种典型场景：同类调用、非 public、异常被吞、`rollbackFor` 没配、传播行为错误、多数据源/多线程、类不受 Spring 管理。

**Q：为什么同类方法调用事务不生效？**

`this.method()` 调用的是原始对象，不是代理对象。代理只在外部通过 Bean 引用调用时才生效。解决：注入自身、`AopContext.currentProxy()`、拆到另一个 Bean。

**Q：@Transactional 默认回滚哪些异常？**

`RuntimeException` 和 `Error`。受检异常默认不回滚，需要 `rollbackFor = Exception.class`。

**Q：多个切面的执行顺序？**

用 `@Order` 或实现 `Ordered` 控制，值越小优先级越高。进入时高优先级先执行，退出时高优先级后执行，形成栈式结构。

**Q：AOP 能拦截 private 方法吗？**

不能。JDK 代理只能拦截接口方法；CGLIB 只能覆写非 private、非 final 方法。private 方法上的注解不会生效。
