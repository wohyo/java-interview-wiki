# 27. 分布式事务

**Q：常见分布式事务方案？**

1. 2PC（两阶段提交）

```
准备阶段：协调者问所有参与者"能提交吗？"
提交阶段：全部 yes → 提交；任一 no 或超时 → 回滚
```

缺点：同步阻塞、单点故障、协调者挂了所有资源被锁住

2. TCC（Try-Confirm-Cancel）

```
Try：预留资源（冻结库存）
Confirm：确认执行（真正扣库存）
Cancel：取消（释放冻结库存）
```

优点：性能好，不用锁资源

缺点：对业务侵入大，需实现 Try/Confirm/Cancel 三个方法

3. 消息最终一致性（MQ + 本地消息表）

```
1. 发送半消息（prepare）：MQ 暂不投递
2. 执行本地事务
3. 提交/回滚消息：提交后 MQ 才投递
4. 消费方处理，失败则重试
```

优点：高可用，无同步阻塞

缺点：最终一致（非强一致）

4. Seata AT

自动生成回滚 SQL（before image 和 after image），开发者无需感知

类似 TCC 的自动化方案，适合简单场景
