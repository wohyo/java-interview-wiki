# 11. volatile

**Q：volatile 能保证什么？不能保证什么？**

保证：

1. 可见性：写 volatile 变量后立即刷新到主内存，其他线程读时从主内存重新读取（禁止寄存器/缓存

优化）

2. 禁止指令重排序：插入内存屏障（LoadLoad、LoadStore、StoreStore、StoreLoad），禁止

volatile 读写前后重排

不保证：

原子性：`count++` （读-改-写）仍需要 synchronized 或 AtomicInteger

例：两个线程同时 `volatile int i = 0; i++;` → 结果可能为 1 而不是 2

**⚡ Q：volatile 的底层实现（内存屏障）？**

写 volatile：插入 `StoreStore` 屏障（禁止前面的普通写与 volatile 写重排）+ `StoreLoad` 屏障（强制刷新到主存，让其他 CPU 失效缓存行）

读 volatile：插入 `LoadLoad` 屏障（禁止 volatile 读与后面的普通读重排）+ `LoadStore` 屏障

Intel x86：volatile 写 ≈ `mfence` 或 `lock addl` 指令，直接强制写回内存并失效其他核心缓存
