# 10. synchronized 原理

**Q：synchronized 的锁升级过程？**

```
偏向锁 (Biased Locking)
↓ 多线程竞争
轻量级锁 (CAS 自旋)
↓ 自旋超过阈值 / 自旋线程太多
重量级锁 (OS 互斥量，Mutex)
```

偏向锁：锁对象的 Mark Word 记录线程 ID。同一线程再次进入只检查，不做 CAS，性能极高

轻量级锁：CAS 尝试将 Mark Word 指向线程栈中的 Lock Record。失败则自旋

重量级锁：线程阻塞，等待 OS 调度（用户态→内核态切换，开销大）

**⚡ Q：锁可以降级吗？**

理论上不能降级（偏向→轻量→重量不可逆）

JVM 在全局安全点（SafePoint）时会做偏向锁的批量撤销/batch rebias，但这并非严格意义上的降级

关闭偏向锁：`-XX:-UseBiasedLocking` （低竞争场景可减少暂停时间）
