# 23. 缓存穿透、缓存击穿、缓存雪崩

**Q：缓存穿透、击穿、雪崩分别是什么？怎么解决？**

| 问题 | 现象 | 解决 |
| --- | --- | --- |
| 缓存穿透 | 查询不存在的数据，每次都穿透到DB | ① 布隆过滤器（Bloom Filter）拦截 ② 缓存空值（短 TTL） |
| 缓存击穿 | 单个热点 key 过期，大量请求打到DB | ① 互斥锁（SETNX）② 逻辑过期（不设物理过期） |
| 缓存雪崩 | 大量 key 同时过期 / Redis 宕机 →DB 被打爆 | ① TTL 加随机值 ② 集群/主从 ③ 限流降级 ④多级缓存 |

**🔥 Q：布隆过滤器的原理和缺点？**

原理：一个超大的 bit 数组 + 多个哈希函数。添加 key 时将多个 hash 位置 1。查询时如果任一hash 位为 0 → 一定不存在（可拦截穿透）

缺点：存在误判率（可能把一个不存在的 key 判为存在）→ 少量穿透仍可能发生。不支持删除

误判率调整：增加 bit 数组大小和哈希函数数量可降低误判率，但增加内存

**🔥 Q：缓存击穿的互斥锁解决方案具体怎么实现？**

```
public String getData(String key) {
String value = redis.get(key);
if (value != null) return value;  // 缓存命中直接返回
```

```
// 缓存不命中，尝试加锁
String lockKey = "lock:" + key;
if (redis.setnx(lockKey, "1", 10, TimeUnit.SECONDS)) {
// 获取锁的线程去查 DB
value = db.query(key);
redis.set(key, value, 300, TimeUnit.SECONDS);
redis.del(lockKey);
return value;
} else {
// 其他线程等待一会重试
Thread.sleep(50);
return getData(key);  // 递归重试
}
}
```
