# 7. ConcurrentHashMap

**Q：ConcurrentHashMap 1.7 和 1.8 的结构区别？**

1. 7：Segment 数组 + HashEntry 数组。Segment 继承 ReentrantLock。默认 16 个 Segment，并发度 16。锁粒度粗

```
static class Segment<K,V> extends ReentrantLock {
transient volatile HashEntry<K,V>[] table;
}
```

1. 8：CAS + synchronized 锁单个桶（Node/数组元素）。锁粒度更细，并发度更高

```
// 插入时
if (tabAt(tab, i) == null)     // 桶空 → CAS 插入
casTabAt(tab, i, null, new Node(...));
else                           // 桶不空 → synchronized(桶头节点)
synchronized (f) { ... }
```

**🔥 Q：为什么 1.8 ConcurrentHashMap 用 synchronized 而不是 ReentrantLock？**

1. JVM 优化：JDK 1.6 后 synchronized 做了大量优化（偏向锁→轻量→重量），性能已追平

ReentrantLock

2. 不需要超时、可中断等高级功能：ConcurrentHashMap 的锁只保护桶内操作，粒度极细

3. 代码简洁：synchronized 自动释放锁，无需 try-finally

4. 空间：synchronized 不产生额外对象（锁在对象头 Mark Word 上），而 ReentrantLock 需要

Node 对象额外持有一个 Lock
