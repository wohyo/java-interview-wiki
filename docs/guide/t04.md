# 4. 反射与动态代理

**Q：反射能做什么？**

运行时获取类的构造器、方法、字段并操作

突破 private 限制（`setAccessible(true)` ）

框架基石：Spring IoC/DI、MyBatis Mapper 代理、Hibernate ORM

**⚡ Q：反射的性能问题？为什么慢？**

1. 方法查找：每次调用需遍历类的方法表（`getMethod` 是 O(n)）

2. 类型检查：`invoke` 内部做参数类型装箱、安全检查

3. JIT 无法内联：反射调用链路长，JIT 难以优化

4. 优化：`setAccessible(true)` 跳过安全检查可提升 20-30%；缓存 Method 对象到 Map 避免重复

**Q：JDK 动态代理 vs CGLIB 代理的区别？**

两者都是在运行时生成代理类，差别在于"怎么生成"。

JDK 动态代理基于接口：`Proxy.newProxyInstance` 生成一个实现了目标接口的代理类，所有方法调用统一转给 `InvocationHandler.invoke()`，增强逻辑写在那里。所以前提是目标类必须有接口。

CGLIB 基于继承：用 ASM 生成目标类的子类，覆写方法并在其中插入拦截器（`MethodInterceptor`）。所以目标类和方法不能是 final，否则没法继承和覆写。

速度要分两段看。创建代理对象：JDK 快，本质只是一次 API 调用；CGLIB 慢，要生成字节码再加载。调用方法：CGLIB 更快，是直接的子类方法调用；JDK 每次走反射，不过 Java 8 之后反射优化过，差距已经很小。

框架选择：Spring 默认有接口用 JDK 动态代理，没有接口才用 CGLIB；Spring Boot 2.x 起把 `proxyTargetClass` 默认改为 true，即统一用 CGLIB。
