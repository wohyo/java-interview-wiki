# 13. 线程池

**Q：线程池七大参数？**

```
public ThreadPoolExecutor(int corePoolSize,        // 核心线程数（常驻）
int maximumPoolSize,     // 最大线程数
long keepAliveTime,      // 非核心线程空闲存活时间
TimeUnit unit,           // 时间单位
BlockingQueue<Runnable> workQueue,  // 工作队列
ThreadFactory threadFactory,        // 线程工厂
RejectedExecutionHandler handler    // 拒绝策略
)
```

流程：

`corePoolSize → workQueue → maximumPoolSize → ``拒绝策略`

**⚡ Q：线程池的线程数如何设置？**

CPU 密集型：`N + 1` （N = CPU 核数）

IO 密集型：`2N` 或 `N / (1 - ``阻塞系数``)`

阻塞系数 ≈ 0.8~0.9 → 线程数 ≈ `N / (1-0.8) = 5N`

混合型：拆分 CPU 密集和 IO 密集的线程池

实际建议压测：请求耗时、QPS、CPU 使用率综合判断

**⚡ Q：四种拒绝策略？**

1. AbortPolicy（默认）：抛 `RejectedExecutionException`

2. CallerRunsPolicy：调用者线程自己执行（压回去，反压效果）

3. DiscardPolicy：静默丢弃（不报错，容易丢任务）

4. DiscardOldestPolicy：丢弃队列中最老的未处理任务，再提交当前任务

**🔥 Q：execute() 和 submit() 底层区别？**

`execute(Runnable)` ：直接提交，无返回值。异常在任务线程内部抛出（会吞掉？不，未捕获异常由线程的 `UncaughtExceptionHandler` 处理）

`submit(Callable/Runnable)` ：返回 `Future&lt;?&gt;` 。异常被捕获存到 `Future` 内部，`future.get()` 时抛 `ExecutionException`

execute 的坑：如果没自定义 ThreadFactory 的 UncaughtExceptionHandler，异常打印到控制台但不中断线程池，后续任务继续执行
