# 12. AQS

**Q：AQS 的核心原理？**

AbstractQueuedSynchronizer，JUC 锁和同步器的基类

核心组件：

1. volatile int state — 同步状态（ReentrantLock：0=无锁，>0 为重入次数）

2. CLH 变体双端队列 — 等待线程队列（FIFO）

3. tryAcquire / tryRelease — 子类实现具体获取/释放逻辑

流程：尝试获取 state → 失败 → 包装为 Node 入队 → 自旋 + park 等待

**🔥 Q：ReentrantLock 公平锁和非公平锁的区别？**

非公平锁（默认）：`lock()` 直接 tryAcquire CAS 抢锁。抢不到再入队。吞吐量更高（减少线程唤醒开销）

公平锁：`hasQueuedPredecessors()` 检查队列是否有前驱节点。有则直接入队等待，不抢锁

性能差异：非公平锁减少线程 park/unpark 次数（刚释放锁的线程可能马上重新获取），高并发下吞吐量高 2~3 倍

**🔥 Q：Condition 的实现原理？**

Condition 内部维护一个单向等待队列

`await()` ：释放锁 → Node 入条件队列 → park

`signal()` ：条件队列的头节点转移到 AQS 同步队列 → 准备竞争锁

与 `wait/notify` 的对比：一个 ReentrantLock 可以 new 多个 Condition，粒度更细（如BlockingQueue 区分 notFull 和 notEmpty）
