# 12. AQS

**一句话定位**：AQS（`AbstractQueuedSynchronizer`）是 JUC 的“锁骨架”——用一个 `volatile int state` 表示同步状态，用一个 CLH 变体队列管理等待线程，子类只实现“怎么改 state”，排队、阻塞、唤醒全部由基类完成。

## 一、三大核心

```java
public abstract class AbstractQueuedSynchronizer {
    private volatile int state;          // 同步状态
    private transient volatile Node head; // 队列头（哨兵节点）
    private transient volatile Node tail; // 队列尾
}
```

| 组件 | 作用 |
| --- | --- |
| `state` | 同步状态。`ReentrantLock`：0 表示无锁，>0 是重入次数；`Semaphore`：剩余许可数；`CountDownLatch`：剩余计数 |
| CLH 变体队列 | 双向 FIFO 队列，抢不到锁的线程包装成 `Node` 入队并 park |
| 模板方法 | `tryAcquire` / `tryRelease` / `tryAcquireShared` / `tryReleaseShared` 由子类实现 |

`state` 的修改全部靠 CAS（`compareAndSetState`），保证可见性和原子性。

## 二、Node 的等待状态

```java
static final class Node {
    static final int CANCELLED =  1;   // 已取消（超时/中断）
    static final int SIGNAL    = -1;   // 后继节点需要被唤醒
    static final int CONDITION = -2;   // 在 Condition 条件队列中等待
    static final int PROPAGATE = -3;   // 共享模式下需要向后传播唤醒
    volatile int waitStatus;
    volatile Node prev, next;
    volatile Thread thread;
}
```

`waitStatus` 最关键的是 `SIGNAL`：一个节点的状态是 `SIGNAL`，表示“我释放锁时必须唤醒我的后继”。

## 三、独占模式：acquire / release

`ReentrantLock.lock()` 最终调用 `AQS.acquire(1)`：

```java
public final void acquire(int arg) {
    if (!tryAcquire(arg) &&                        // ① 先试着直接拿
        acquireQueued(addWaiter(Node.EXCLUSIVE), arg))  // ② 失败则入队并阻塞
        selfInterrupt();
}

private Node addWaiter(Node mode) {
    Node node = new Node(Thread.currentThread(), mode);
    Node pred = tail;
    if (pred != null) {
        node.prev = pred;
        if (compareAndSetTail(pred, node)) {       // CAS 入队
            pred.next = node;
            return node;
        }
    }
    enq(node);                                      // 队列为空或 CAS 失败，自旋入队
    return node;
}

final boolean acquireQueued(final Node node, int arg) {
    boolean interrupted = false;
    for (;;) {
        final Node p = node.predecessor();
        if (p == head && tryAcquire(arg)) {          // 前驱是头节点才允许再试一次
            setHead(node);
            p.next = null;
            return interrupted;
        }
        if (shouldParkAfterFailedAcquire(p, node) && // 把前驱状态改成 SIGNAL
            parkAndCheckInterrupt())                 // LockSupport.park() 真正阻塞
            interrupted = true;
    }
}
```

整个过程可以概括为：

```
tryAcquire 成功 → 直接返回
失败 → 包装成 Node 入队 → 前驱是 head 就再试一次 → 仍失败则 park
被唤醒 → 检查自己是不是 head 的后继 → 是则 tryAcquire → 成功则出队
```

::: tip
**只有前驱是 head 的节点才有资格尝试获取锁**，这是 FIFO 公平性的来源（非公平锁在入队前还会插队试一次）。

:::

释放：

```java
public final boolean release(int arg) {
    if (tryRelease(arg)) {                  // 子类实现：state 减到 0 才算真正释放
        Node h = head;
        if (h != null && h.waitStatus != 0)
            unparkSuccessor(h);              // 唤醒 head 的后继
        return true;
    }
    return false;
}
```

## 四、ReentrantLock 怎么用 AQS

```java
static final class NonfairSync extends Sync {
    final void lock() {
        if (compareAndSetState(0, 1))          // 非公平：先插队抢一次
            setExclusiveOwnerThread(Thread.currentThread());
        else
            acquire(1);
    }

    protected final boolean tryAcquire(int acquires) {
        final Thread current = Thread.currentThread();
        int c = getState();
        if (c == 0) {
            if (compareAndSetState(0, acquires)) {   // 公平锁这里多一个 hasQueuedPredecessors()
                setExclusiveOwnerThread(current);
                return true;
            }
        } else if (current == getExclusiveOwnerThread()) {
            int nextc = c + acquires;                 // 重入：state + 1
            if (nextc < 0) throw new Error("Maximum lock count exceeded");
            setState(nextc);
            return true;
        }
        return false;
    }
}

protected final boolean tryRelease(int releases) {
    int c = getState() - releases;
    if (Thread.currentThread() != getExclusiveOwnerThread())
        throw new IllegalMonitorStateException();
    boolean free = false;
    if (c == 0) {                                     // 重入次数减到 0 才释放
        free = true;
        setExclusiveOwnerThread(null);
    }
    setState(c);
    return free;
}
```

**公平与非公平的唯一差别**就在 `tryAcquire` 里多一句 `hasQueuedPredecessors()`：

- 非公平：`lock()` 先 CAS 抢一次，抢不到再入队；被唤醒后也可能被新来的线程插队。
- 公平：只要队列里有前驱，就直接入队，不抢。

非公平吞吐更高（减少 park/unpark 次数），公平能避免饥饿。默认是非公平。

## 五、共享模式

`tryAcquireShared` 返回值有约定：负数失败、0 成功但后续无法再获取、正数成功且后续还能获取。

| 工具 | state 含义 | 实现要点 |
| --- | --- | --- |
| `Semaphore` | 剩余许可数 | `tryAcquireShared` 用 CAS 减许可；减到 0 后新线程排队 |
| `CountDownLatch` | 剩余计数 | `countDown` 用 CAS 减 1，减到 0 时唤醒所有共享节点 |
| `ReentrantReadWriteLock` | 高 16 位读锁、低 16 位写锁 | 一个 state 拆两段，读读共享、读写互斥 |

`CountDownLatch` 的 `await()` 就是 `acquireSharedInterruptibly(1)`，`countDown()` 就是 `releaseShared(1)`。

## 六、Condition 的原理

`Condition` 是 `synchronized + wait/notify` 的替代品，一个 `ReentrantLock` 可以创建多个 Condition，实现**分组唤醒**（`ArrayBlockingQueue` 用 `notFull` 和 `notEmpty` 两个条件，避免唤醒无关线程）。

内部有两套队列：

```
同步队列（AQS）：head ↔ Node ↔ Node ↔ tail      ← 等待锁
条件队列（Condition）：firstWaiter ↔ Node ↔ ...  ← 调用 await 后在这里
```

`await()` 的流程：

1. 检查当前线程持有锁，否则抛 `IllegalMonitorStateException`；
2. 把当前线程包装成 `CONDITION` 节点加入条件队列；
3. **完全释放锁**（`release(savedState)`，包括重入次数）；
4. `park()` 阻塞；
5. 被 `signal()` 转移回同步队列后，重新 `acquire` 抢锁；
6. 抢到锁后从 `await` 返回，此时 state 恢复为原来的重入次数。

`signal()` 的流程：把条件队列的头节点从 `CONDITION` 改成 `SIGNAL`（或 0），转移到同步队列尾部。**它不会立刻释放锁**，当前线程仍持有锁，直到退出同步块。

`signal` 与 `notify` 的差异：

| 维度 | `Object.wait/notify` | `Condition.await/signal` |
| --- | --- | --- |
| 条件队列数量 | 一个对象一个 | 一把锁可以多个 |
| 唤醒粒度 | `notify` 随机唤醒一个 | 指定 Condition，精确唤醒 |
| 等待时可中断 | 支持 | 支持（`await` 抛 `InterruptedException`） |
| 超时 | `wait(timeout)` | `await(timeout, unit)` |
| 使用前提 | 持有 monitor | 持有 Lock |

## 七、面试连环问

**Q：AQS 的核心思想？**

用一个 `volatile int state` 表达同步状态，用 CAS 修改，用 CLH 变体队列管理等待线程；基类负责入队、阻塞、唤醒，子类只实现状态怎么变。这是**模板方法模式**的典型应用。

**Q：为什么 AQS 用双向队列而不是单向？**

唤醒时需要从尾部向前找有效节点（`unparkSuccessor` 从 `tail` 往前找 `waitStatus <= 0` 的节点），`CANCELLED` 节点需要能被跳过和清理；`prev` 指针让取消和查找更高效。入队也依赖 `prev` 做 CAS。

**Q：公平锁和非公平锁的区别？**

公平锁在 `tryAcquire` 里用 `hasQueuedPredecessors()` 检查有没有前驱，有就排队；非公平锁直接 CAS 抢。非公平吞吐更高，公平避免饥饿。

**Q：AQS 的 state 是 volatile 的，为什么还要 CAS？**

`volatile` 只保证可见性和有序性，`state++` 这类读-改-写仍需原子性，所以用 `compareAndSetState`。

**Q：Condition 的 await 为什么会释放锁？**

`await` 内部调用 `fullyRelease(node)` 把 state 释放到 0 并唤醒后继，然后 park。不释放锁的话，其他线程无法进入同步块去 `signal`，会死锁。

**Q：CountDownLatch 和 CyclicBarrier 的区别？**

`CountDownLatch` 是一次性的，基于 AQS 共享模式，计数减到 0 后不可重置；`CyclicBarrier` 基于 `ReentrantLock + Condition`，可循环使用，等的是“一组线程互相到齐”。前者是“一个线程等多个线程完成”，后者是“多个线程互相等待”。

**Q：AQS 支持中断吗？**

支持。`acquireInterruptibly` 在 park 返回后检查中断标志，若被中断则抛出 `InterruptedException` 并从队列中取消节点。普通 `acquire` 只是记录中断、不抛出，等拿到锁后再 `selfInterrupt()` 补上标志。
